# 牌背预设、房间体验与 GOD Slayer 设计

日期：2026-06-18

## 目标

在不破坏现有游戏和卡组上传流程的前提下完成三组改动：

1. 为上传卡组增加由默认牌背实时改色并直接上传的预设弹窗。
2. 改善主菜单、等待室、公开房间列表、设置页和详细说明页的玩家体验。
3. 以服务端权威判定和持久化方式加入 GOD Slayer 称号、奖励弹窗、专属音效、动态字体子集和全站用户名样式。

用户已经修改的现有前端文案和工作区中的资源文件必须保留，不得用回退、清理或覆盖方式处理。

## 总体架构

- Spring 后端负责 GOD Slayer 资格判断、称号授予、奖励待确认状态、确认接口和字体子集生成。
- Vue 前端负责牌背像素处理、弹窗交互、用户名语义组件、奖励展示和音效分流。
- PostgreSQL 的 `cof_user_stats` 继续作为称号和奖励状态的权威数据源。
- Redis 中的 `Game` 保存本局新晋 GOD Slayer 的赢家 ID，使所有客户端能立即选择正确的结算样式和音效，但奖励待确认详情只通过赢家自己的 profile 返回。
- 所有用户名样式通过明确的用户名组件渲染，不扫描、替换或重写普通页面文本。

## 1. 牌背预设弹窗

### 入口与交互

- 在“2. 上传牌背”区域保留现有图片裁剪上传入口，并增加“使用预设”按钮。
- 未选中“我的提交”中的当前卡组时，预设入口不可确认，并给出选择卡组的明确提示。
- 点击“使用预设”打开弹窗，不跳转路由，也不丢失当前卡组、PMV 或上传表单状态。
- 弹窗包含：默认牌背实时预览、颜色轮、当前颜色值、取消按钮、确认并上传按钮以及上传错误提示。
- 点击“确认并上传”后直接将改色结果上传到当前卡组，不再要求用户回到上传区点击第二次上传按钮。
- 上传成功后关闭弹窗、刷新“我的提交”并沿用现有成功提示；上传失败时保留弹窗、颜色和预览，允许直接重试。

### 默认资源与像素算法

- 使用仓库中的 `cof-resource/cards/placeholder.png`。浏览器通过后端现有资源路由读取 `/cards/placeholder.png`。
- 将源像素转换为亮度 `L`，其中 `L` 在 0 到 1 之间。
- 对 RGB 每个通道应用线性插值：`output = selected + L * (255 - selected)`。
- 因此纯黑映射为所选颜色，纯白仍为纯白，中间亮度平滑映射到所选颜色与白色之间。
- Canvas 阶段保留透明度；生成上传 Blob 后继续由现有后端图片处理器统一裁剪、压缩和保存为牌背 JPEG。
- 像素算法放入独立纯函数，覆盖黑、白、中灰、彩色源像素、透明像素和边界颜色测试。

### 组件边界

- `CardBackPresetModal.vue`：弹窗状态、颜色轮、预览、确认与错误展示。
- `cardBackPreset.ts`：加载图片、亮度映射、Canvas 输出 Blob 的纯逻辑。
- `CardSubmitView.vue`：只负责当前卡组上下文、打开弹窗、调用现有 `uploadSubmissionBack` 并刷新提交列表。

## 3. GOD Slayer 服务端规则

### 资格条件

仅当以下条件在同一局结束时全部满足，才授予称号：

1. 本局有效 `game.settings.libraryIds` 非空，并且每一个牌组 ID 都属于 `{ "1", "2" }`；可以只使用其中一个，也可以同时使用，`libraryCopies` 份数任意。
2. 本局存在 `computerId = "computer_god"` 的 GOD，且 GOD 已被淘汰。
3. 赢家存在、不是电脑，并且赢家最终剩余摸牌堆数量至少为 3。
4. 赢家此前还不是 GOD Slayer。

只有赢家可以新获称号。其他排名高于 GOD 的玩家不获称号。已经拥有称号的赢家不会再次收到奖励弹窗，结算时使用普通结束音效。

### 数据模型

沿用 `cof_user_stats` 已有字段：

- `god_defeated_at`：永久称号标记，非空即表示拥有 GOD Slayer，奖励确认后也不会清空；
- `god_reward_game_id`：待确认奖励标记，非空表示仍有待确认奖励；确认奖励时清空该字段；
- `defeated_computers`：继续维护电脑击败统计。

不新增任何数据库字段、表、索引或约束，也不需要 Flyway 迁移或其他 schema 变更。详细状态约定记录在 `docs/database/god-slayer-persistence.md`。

### 授予与幂等

- 资格检查在保存结束战绩的服务端路径中执行，使用 `Game.settings` 和结束时玩家状态，不信任前端参数。
- `GameSummary.SummaryPlayer` 增加判断所需的淘汰状态；最终摸牌堆数量继续使用 `finalDrawCount`。
- 首次授予时设置 `god_defeated_at` 和 `god_reward_game_id`；前者永久保留，后者表示奖励待确认。
- `Game` 和 `PublicGame` 增加 `godSlayerAwardWinnerId`，仅在本局确实新授予称号时设置。
- 依靠既有唯一 `game_id`、`statsSaved` 和数据库条件更新避免重复 tick 或重试重复授予。
- GOD 的普通击败统计改为服从新资格条件；其他电脑的击败统计保持原逻辑。

### 公有称号与私有奖励

- `godSlayer` 是可以公开展示的玩家属性，加入认证玩家、房间玩家详情、游戏玩家、结算玩家、排行榜和个人资料 DTO。
- `godSlayerAwardWinnerId` 可随 PublicGame 广播，用于结算音效与即时样式。
- `pendingGodSlayerReward` 只在当前登录用户自己的 profile 中返回；其他玩家无法读取赢家是否已经点击“收下”。
- 新增奖励确认接口。它只能确认当前登录用户的待领取奖励，成功后清空 `god_reward_game_id`，但永久保留 `god_defeated_at`。
- 如果赢家刷新或重连，profile 仍返回待领取奖励，弹窗重新出现，10 秒倒计时从头开始。

## 4. 奖励弹窗与音效

### 弹窗内容

弹窗覆盖在普通结算之上，只对本局新获称号的真人赢家展示：

> 恭喜！！！
>
> 你击败了帧封相对之神，胜天至少三子！以后，你的名字会以更醒目的样式出现在所有玩家列表和对局里！
>
> 请截图这个页面发给页面下方的作者，领取**弑神纪念奖励——一份CSBC'25的PMV静帧扑克牌**！
>
> 你的用户名：{用户名}

- “恭喜！！！”居中、大号、粗体。
- 用户名立即使用 GOD Slayer 金色样式。
- “收下”按钮显示剩余秒数，弹窗出现 10 秒后才可点击。
- 刷新或重连后弹窗仍出现，倒计时重新从 10 秒开始。
- 点击“收下”调用确认接口；成功才关闭。失败时保留弹窗并允许重试。

### 音效分流

- 本局新晋 GOD Slayer 的赢家不播放普通对局结束音效，只播放 `cof-resource/audio/cheers.mp3`，浏览器路径为 `/audio/cheers.mp3`。
- 同一局的其他玩家继续播放普通对局结束音效。
- 已经拥有称号的赢家不会得到 `godSlayerAwardWinnerId`，因此仍播放普通结束音效。
- 每次页面加载只触发一次相应结算音效；刷新后待领取弹窗重新出现时，赢家可以再次听到 cheers。

## 5. 用户名组件、动画与字体子集

### 语义化用户名渲染

新增统一 `PlayerName.vue`，输入至少包括：

- `username`；
- `godSlayer`；
- `isGod`，由电脑 ID `computer_god` 或明确的 GOD 玩家属性决定；
- 字体子集标识所需的 `statsId`。

优先级为 GOD 身份高于 GOD Slayer，避免同一节点同时应用两套效果。

组件应用于所有明确的玩家用户名槽位，包括：顶部当前用户、公开房间玩家、等待室、房主转让、人机选择、对局座位、聊天发送者、结算标题与图例、排行榜、个人资料/历史以及回放中的玩家名称。普通说明文字、数字、版本号和自由文本日志不做字符串替换，避免误伤同名片段。

### 动画样式

- GOD Slayer：金色、思源宋体、粗体，使用金色多层 `text-shadow`。
- GOD：浅红色、思源宋体、粗体，使用浅红色多层 `text-shadow`。
- 两者使用约 2.5 至 3 秒的缓动循环，使光晕轻微扩散和收缩。
- 动画只改变光晕强度和半径，不改变文字位置、字号或布局。
- 尊重 `prefers-reduced-motion`：减少动态时保留静态光晕。

### 动态字体子集

- 字体源使用 `old/SourceHanSerifSC-VF.otf.woff2`，不会把 19 MB 完整字体发送给浏览器。
- GOD 使用固定仅含 `GOD` 必要字符的子集。
- GOD Slayer 使用对应 `statsId` 的字体端点；服务端从权威用户名提取去重字符，不接受客户端任意文本作为最终字符集。
- 服务端通过 FontTools 生成 WOFF2，以源字体版本和字符集的 SHA-256 命名，写入 `cof-resource/assets/fonts/name-subsets` 缓存。
- 同一字符集只生成一次；并发请求使用每键锁和临时文件原子替换。
- 前端 `PlayerName` 通过 FontFace API 加载对应子集并仅应用到该用户名节点。
- 奖励弹窗出现时立即预加载字体，10 秒等待期同时作为子集生成窗口。
- 字体生成失败时回退到系统宋体、记录错误并允许下次请求重试；称号、弹窗和结算不被阻塞。

## 6. 注册名限制

- 注册页在用户名输入附近明确显示：`用户名不能包含 GOD（不区分大小写）。`
- 提交注册前，前端对 trim 后的名字做大小写不敏感的包含检查并立即提示。
- 后端再次执行同样检查；任何包含 `GOD` 的注册名（包括 `GOD` 本身及 `godzilla` 等）都被拒绝。
- 后端错误信息明确写为：`You lowlife. 用户名不能包含 GOD（不区分大小写）。`
- 限制只作用于新用户注册；既有账号登录和 `computer_god` 人机身份不受影响。

## 7. 错误处理

- 牌背源图加载失败：禁用确认上传并显示资源加载错误。
- 牌背上传失败：保留弹窗和选择颜色，允许重试。
- Clipboard 失败：显示失败提示，不伪报复制成功。
- 奖励确认失败：弹窗保持打开，按钮恢复可点击。
- 字体生成失败：回退系统宋体并记录服务端错误，不影响称号授予。
- profile 或结算刷新暂时失败：沿用现有错误恢复机制；服务端持久化状态保证下次刷新仍可恢复弹窗。

## 8. 测试与验收

### 后端自动化测试

- GOD Slayer 资格矩阵：仅牌组 1、仅牌组 2、牌组 1+2、任意份数、混入其他牌组、空牌组、GOD 未淘汰、电脑赢家、赢家不足三张、赢家至少三张、已有称号。
- 只有赢家获称号；其他排在 GOD 前的人不获称号。
- 重复结束 tick 和重复保存不会重复授予。
- pending reward 只出现在赢家自己的 profile，确认后消失。
- 注册名对 `GOD` 的大小写不敏感包含检查。
- 字符去重、缓存键、并发缓存和失败回退。
- 私密房间不进入公开房间列表响应。

### 前端自动化测试

- 牌背映射的黑、白、中间亮度和 alpha 行为。
- 预设确认直接上传当前卡组，失败时保留状态。
- 房间列表只渲染公开房间并显示用户名、卡组名称/份数和规则，不显示投票。
- `PlayerName` 只在语义用户名节点添加 GOD/GOD Slayer 类，不污染其他文本。
- 奖励按钮 10 秒前不可用，刷新组件后重新计时，确认失败可重试。
- 新晋赢家使用 cheers 且不播放普通结束音效；其他玩家和既有称号赢家使用普通音效。
- 注册页提示和前端 GOD 包含校验。

### 构建与人工验收

- 运行前端 Vitest 和 `npm run build`。
- 运行相关 Maven 模块测试；再按仓库现状运行后端 package/verify，并如实记录分支已有失败。
- 服务可启动时，用本地浏览器检查牌背弹窗、公开房间、复制按钮、用户名动画、字体网络体积、奖励倒计时和音效互斥。
- 最终提交前检查用户原有文案修改和资源文件仍然存在，再提交并推送 `feature-dyu`。
